---
name: quercus-lecture-notes
description: Inspect each Quercus course's structure and sync its lecture notes, adapting selection to its actual files, modules and pages.
---
Work from the Quercus project root. List courses if needed, then run `python3 quercus.py download COURSE_ID --preview`. Inspect selected and unselected titles, IDs, module/folder names and lecture-page link labels. The tool uses the course Files listing or, if restricted, accessible module items and links on lecture-named pages. Course layouts differ: lecture files can be grouped in modules, linked from pages, or named by chapter; symbols and labels are not universal.

For each lecture or topic, inspect available note variants using titles, page-link labels, module context and, where necessary, accessible file content. If a completed, filled-in or annotated version corresponds to an empty, blank, skeleton or unannotated version, include the completed version and exclude the empty one by default using file IDs. If a page links to a separate completed-notes index, inspect that same-course page for accessible file links and compare them with the lecture's empty notes. Include notes from other lectures even when they only have an empty version, and report that no completed version was found. If the pairing or completeness is uncertain, report it and ask the student instead of silently discarding files. Respect a student's explicit request for both versions. Do not rely on course-specific names, and do not delete previously downloaded empty notes. The Python downloader itself does not choose between variants; apply these choices to the exact preview and download commands using include and exclude IDs.

Determine likely lecture notes from this course's actual structure and context, distinguishing notes and slides from videos, exercises, assignments, solutions and syllabi. When classification is ambiguous, explain the uncertainty and ask the student; don't assume all linked files are notes. Use `--include-id` or `--include-pattern` for likely omissions and `--exclude-id` or `--exclude-pattern` for false positives; patterns are case-insensitive regular expressions and exclusions take precedence. Preview again with the exact options before running the download. Explicitly tell the student which material remains inaccessible, ambiguous, external or uninspected, and offer local document import. Do not claim the course is complete just because sync ran. Existing files, including remote updates, are not overwritten.

If the preview omits important content, inspect the course's accessible module and page metadata using read-only Canvas API calls, respecting permissions. Follow only same-origin, same-course file links; do not copy access tokens or verifier-bearing URLs into chat, logs or external services. Do not retrieve external links automatically. The selection should generalize by inspecting each course, not by relying on a hard-coded course ID or symbol. Use the local `.env` or an existing QUERCUS_TOKEN; never ask the student to share the token in chat.
